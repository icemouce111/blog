# 博客安全运行与验收

博客继续公开代码、文章与图片。模型在可信生成进程中调用，静态站不持有模型密钥；网站没有在线生成接口。限流只能减少异常流量，不能阻止从公开仓库或前端包复制内容。

## 本地安装与检查

```sh
python3 scripts/install_gitleaks.py
python3 scripts/setup_security.py
python3 -m pip install --require-hashes -r scripts/requirements.lock
npm run security:history
npm run security
npm test
npm run build
```

Gitleaks 固定为 8.30.1，安装时验证官方发布包 SHA-256。Windows 使用官方同版本可执行文件并加入 PATH。本地钩子可被手动绕过，因此 GitHub 推送保护、PR 必需检查和发布器检查必须同时保留。CI 是推送后的检查，无法撤回已经公开的提交。

两个生成器先保留进程环境，再加载 `scripts/.env`，最后加载兼容文件 `scripts/dc-config.env`。仅示例文件可提交。密钥不放入 `VITE_*`、`src/`、`public/`、命令参数、PR、截图或构建设置；不复制到临时 worktree。前端构建与 PR 检查不需要模型密钥。

扫描覆盖 Git 历史、当前非忽略文件、Git 暂存区的实际字节、发布产物和 dist。生成器写公开文件前检查正文，发布器推送前再次检查完整产物。任何扫描失败或工具不可用都会停止发布。报告仅输出脱敏路径和规则，不上传原始发现或密钥。

## PR 发布与凭证

参见 [日报 SOP](ai-daily.md)。发布器只创建日报 PR；身份必须与 PR 作者一致，禁止跨仓库 PR，完整分页验证文件白名单。检查 head 不变且三个必需检查成功后才请求自动合并。冲突不强推，超时重跑复用原 PR。

推荐发布凭证限定本仓库 `Contents: write`、`Pull requests: write`，不能修改管理设置或绕过主分支保护。现有 gh 登录可运行发布器，但其账号凭证范围需自行确认；代码不能缩减已经授予外部凭证的权限。

## Cloudflare 操作与验收

仅使用现有套餐，不替换不相关规则、不购买升级。配置前记录已有规则 ID、顺序及 Pages 项目默认域名。

1. 保留正式域名公开访问，将生产 `pages.dev` 域名 301 重定向至 `https://blog.icemouce.cc`，保持路径和查询；预览部署开启 Cloudflare Access，仅限维护者。注意预览 Access 不会自动保护生产 `pages.dev`。
2. 创建仅匹配本站 hostname 的敏感路径阻断规则，覆盖 `.env`、`.env.*`、`*.env`、`.git` 及其子路径；不要拦截 `.well-known`、RSS、文章与资源。
3. 文章路由 `/ai-daily`、`/github`、`/blog` 及详情初始按 IP 限制 100 次/10 秒，阻断 10 秒。排除 verified bots、XML 和静态资源。免费套餐表达式不能匹配 Host；若同 Zone 其他站点存在冲突或规则配额已用完，停止此项并记录缺口，不能扩大影响范围。
4. 验证 `public/_headers` 上线，CSP 不阻止正常脚本、字体、图片或路由；验证预览需授权、正式站和 RSS 无需授权，生产默认域名不能绕开规则。
5. 限流通过控制台规则状态及现有安全事件验证，不向生产站发起高频压力请求。没有命中证据时，只能记“已配置，效果待验证”。

当前 `/.env` 的 HTTP 200 可能来自 SPA 首页回退，必须核对响应内容，不能仅凭状态码判定泄漏。路径阻断用于减少探测，不代替产物扫描。CORS、Referer 和前端判断不能作为防反代认证。

## 泄漏与故障处理

发现真实凭证先到对应平台撤销并换新，检查用量与访问记录，再处理历史、缓存、日志、旧部署及受影响材料。不自动强推重写公共历史；Fork 和既有下载无法收回。

扫描误报只能针对具体位置、具体规则记录理由后处理，不能排除整个文章或数据目录。二进制图片内容、个人隐私、二维码、提示注入与第三方素材版权无法仅靠密钥扫描解决，新增图片和客户材料需人工核对。

上线后一周复核 GitHub 检查、发布失败和 Cloudflare 拦截事件，不新增日报定时任务。若误拦访客，先恢复对应边缘规则；保留密钥门禁与主分支保护。
