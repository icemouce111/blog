# 创作者机会的每日搜集与筛选

## 执行位置

继续由现有每日任务调用 `scripts/generate-ai-daily.py`，不新增调度、公开模型接口或付费搜索服务。现有晚间任务与补救检查都使用同一入口。代码 PR 合并到 main 后，隔离生成 worktree 会取得新流程；运行端的 Publisher 白名单也需包含本文件描述的机会 JSON。

当天生成开始时，先运行 `scripts/creator_opportunities.py` 的刷新流程，再将合格机会传给日报编辑。即使文章已存在，仍先进行当天机会刷新。`--dry-run` 可以搜索和调用模型，但不写机会 JSON、文章或派生产物；历史补档不刷新当前机会。同日且来源配置未变的已完成刷新默认复用；来源配置指纹改变会刷新快照，`--force` 也可主动重跑每日部分；四平台仍遵守下述三天间隔。

## 数据与职责

- `src/data/creator-opportunity-sources.json`：人工维护的来源、官方域名、搜索词、起步阶段筛选条件和运行上限。日报发布器无权修改。
- `src/data/ai-opportunities.json`：每日更新的公开快照，保存奖励、门槛、截止、官方入口、适配理由、核验日期与搜集状态。它是唯一新增的可自动发布路径。
- 脚本：执行搜索与来源轮询、去重、保留截止时区说明、检查过期和核验时效、区分官方与非官方、验证模型摘录和金额数字、扫描后写入。
- 规则提取模型：只阅读提供的公开页面，提取规则、区分现金 / 佣金 / 积分 / 流量，判断是否适合不足千粉且每周 5—10 小时的 AI 短视频与个人 IP 路线。无工具执行、文件访问、报名或联系权限。

公开快照不保存模型密钥、来源全文、个人登录态或完整原文摘录。核验摘录只在进程内用于比对；数据输出仍通过通用和运行时已知密钥扫描。

## 每日发现流程

1. 小红书、抖音、推特 / X、公众号每3天运行一轮定向检索，每轮各一次平台域名检索和一次具名站外转述检索。两次通用搜索仍按日轮换；到期日最多10次，间隔日仅2次，最多4路并发，每次超时12秒。覆盖知识共创、流量扶持、征稿、创作者计划及商家接单，不以现金词为必需条件。Bing RSS只用于发现，失败按平台分别记录，搜索完成不等于覆盖所有端内内容。
2. 轮询一个官方活动目录和一个第三方赛事目录。第三方只贡献线索，不提供奖励事实；显示时标记官方入口仍待确认。
3. 四平台与通用来源轮流贡献候选，最多新增 8 条去重线索，未核验的发现线索按最近发现日期保留，避免100条上限阻止新增；每轮最多检查 10 个页面，优先起步阶段的机会，并按上次检查时间轮换。公开网页可能被限流或需要 App，不能保证发现全网所有活动。
4. 只在配置的官方域名和可核验页面上进行自动复核。平台托管的用户帖子不是官方公告：B 站普通视频 / 动态默认不作规则证据。登录页、重定向到其他域名、不可读页面不通过。
5. 对有历史核验 hash 且正文相同的页面，可以更新实际复核日期。页面变更后必须重新取得证据，不能仅凭 HTTP 200 延长核验。
6. 模型返回奖励、门槛和截止的原文摘录；脚本要求摘录确实存在，数字与对应字段一致，积分不得改标现金。不完整、冲突、伪造或无法确认的结果留在待核队列。
7. 已超过截止的条目不展示；缺少有效核验或超过 7 天的条目转为待核；达到千粉 / 万粉门槛或明显偏重的任务放在“后续再看”。

## 四平台发现与待核队列

`platformChannels` 配置目标平台、发现用域名、平台识别词和检索词。站外转述必须匹配具体平台或活动名，记录为secondaryLeads，不充当平台原帖或官方证据。小红书同时识别小红书主站与xhslink分享链接；抖音识别douyin与iesdouyin；X兼容x.com和twitter.com；公众号定位mp.weixin.qq.com。发现域名不会加入官方规则白名单，认证标记和站内帖子也不自动证明主办方身份。

平台线索保存 `discoveryPlatform`、`sourceUrl` 和 `reviewMode: manual`，默认无已确认的官方入口、奖励及截止。`AI替我说／用AI讲知识` 使用独立名称，当前只保留二手来源，不能把蒲公英首页充当活动规则，也不根据海报未写年份的日期推定本年。

`limits.platformSearchIntervalDays` 设置为3，以上海日期计算，从每个平台上次实际尝试的日期相隔3个自然日再检索；失败也进入间隔；`--force` 重跑日报和其他来源时，仍遵守四平台间隔。间隔日保留上次统计和搜集日期，记录下次日期及skipped，不能把沿用结果标为当日新搜集。通用搜索偶然发现的平台线索单记incidentalPlatformDiscoveries，不修改上次定向统计。每日新闻生成、规则复核、过期检查继续运行。

`collection.channels` 记录每个平台计划、完成、失败搜索数及新增线索数；结果页显示四个平台的实际执行状态，旧快照显示“待首次定向搜集”。`collection.reviewQueue` 轮流排列最多12个待核ID，供平台复核Agent或维护者检查账号身份、原帖、奖励、资格和截止。当前Python流程不会登录App、X或微信，也不会执行浏览器Agent；本轮建立并公开待核队列，不将未执行的平台内核验描述为已完成。

已知活动名、共创、征稿、流量券和英文creator program / bounty等同样进入候选，不能因标题未写“活动”就丢弃。搜索引擎忽略site限制时，其他域名的命中不计为平台原帖。公众号普通文章、X普通推文和小红书/抖音用户投稿都须另外核验身份。

## 三类展示

- **优先尝试**：官方规则已核验且适合当前阶段，仍区分可准备投稿与需申请审核。总奖池与个人最高奖不是保底，也不表示用户已符合所有身份条件。
- **待核实线索**：具体任务、官方身份、现金算法、账号资格或截止不完整；逐项显示原因。未知截止不能自动写“长期开放”。
- **达到门槛或有更多时间后再看**：正常商单渠道、高粉丝门槛与重制作比赛。保留价值，但不挤占当前起步推荐。

活动、创作者合作渠道和已经确认的具体订单必须区分。搜索到商家制作需求并不代表用户已接单；没有完整 Brief、资格和付款说明，不给出确定报价或保底收入。不得自动代用户报名、联系商家、买会员或上传素材。

## 来源失败和重新核验

搜集统计记录搜索失败、页面失败和模型状态。部分来源失败不阻塞正常新闻日报；前端显示“部分来源待复核”，失败不能续签旧核验日期。需要登录、官方帐号核验或复杂动态页面的记录使用 `reviewMode: manual`，等待原生 Agent / 维护者根据实际官方规则更新，不能从通用首页推导具体活动。

有价值的新官方来源经维护者核验后再加入域名和入口配置。不要为了自动化提高命中率而信任所有投稿平台、关闭证书校验或把第三方目录升级成官方证据。

## 发布与验收

机会快照与当日报告、RSS、趋势 JSON 同经隔离 worktree、安全扫描、文件白名单和三项 CI 检查发布；配置、脚本和工作流仍需代码 PR 审阅。新增路径不能变成通配目录。

测试覆盖过期 / 冲突 / 未知截止、千粉门槛、核验时效、伪造金额和摘录、积分误标现金、来源失败不续签、同日幂等、历史不抓未来、dry-run 不写入，以及发布器夹带代码拒绝。
